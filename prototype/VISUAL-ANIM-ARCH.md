# Визуально-анимационная архитектура (и как подключить API генерации)

Документ объясняет, как устроены **анимация и графика** в движке и как сюда
подключается твой **API генерации картинок/анимаций**, не меняя логику боя.

## Три слоя и их взаимодействие

```
СИМУЛЯЦИЯ (что произошло)         АНИМАЦИЯ (как это показать)        ГРАФИКА (чем рисовать)
─────────────────────────        ──────────────────────────        ─────────────────────
ai/brain.js, combat/*            anim/animation.js                  render/silhouette.js  ← сейчас
выставляет u.animState:    ───▶  AnimController: state→clip   ───▶  render/sprite.js      ← твоя генерация
walk / windup_high /             + поза-скелет (точки           +   fx.js (кровь/искры/лёд)
strike_mid / hit / dead          привязки handR, head, ...)
```

- **Симуляция** не знает про графику. Она лишь решает события (удар в руку,
  выбито оружие, смерть) и ставит `u.animState` (логическое состояние анимации).
- **Слой анимации** (`anim/animation.js`) переводит `animState` в **клип** и в
  **позу-скелет** с точками привязки. Поза — общая для всех бэкендов рендера.
- **Графика** — сменный бэкенд, реализующий один метод `drawUnit(ctx, u, view)`:
  - `SilhouetteRenderer` — рисует позу процедурно (чёрные силуэты). Работает уже сейчас.
  - `SpriteRenderer` — рисует **сгенерённые спрайты/анимации** по манифесту.

Сменить силуэты на сгенерённую графику = поменять один бэкенд. Логику не трогаем.

## Точки привязки (почему оружие/стрелы цепляются правильно)

И силуэт, и спрайт-бэкенд используют одни и те же якоря: `handR` (кисть с
оружием), `head`, `chest`, ступни. Поэтому меч, торчащая стрела, иней, огонь
рисуются в правильном месте независимо от того, чем рисуем тело.

## Размеры юнитов

Размер задаётся в данных: `data/units.js -> UNIT_TYPES[*].heightW` (в мировых
единицах; мир ~200 ед.). Он влияет и на рендер (высота в px = `heightW*sc`), и на
бой (дистанция удара/обнаружения). Примеры: `imp` 11, `soldier` 15, `brute` 23.
В демо есть слайдер «Размер юнитов» (`view.unitScale`) для быстрой визуальной
подгонки.

## Удары с разных сторон / динамика

- Приём имеет `region: high|mid|low` (`data/moves.js`) → выбирается клип
  `windup_*`/`strike_*` (замах сверху/сбоку/снизу).
- `u.dir`/`u.face` — направление взгляда (всегда к цели), рендер зеркалит позу.
- Динамика: выпад (`lunge` в позе удара), отдача жертвы (`u.knock`), hit-stop
  (короткая фаза `strike`), падение трупа (`deathT` → поворот).

## КАК ПОДКЛЮЧИТЬ ТВОЙ API ГЕНЕРАЦИИ

Твоя генерация выдаёт **спрайт-листы по клипам** + **манифест** (см.
`assets-manifest.example.json`). Пайплайн:

1. **Список нужного.** Для каждого типа юнита нужны клипы: `idle, walk,
   windup_{high,mid,low}, strike_{high,mid,low}, block, hit, prone, dead`
   (имена = ключи в `CLIPS`). Это и есть промпт-план для генерации.
2. **Генерация.** API создаёт спрайт-лист на каждый клип (кадры в ряд) и,
   опционально, отдельный спрайт оружия и оверлеи частей (рана/культя/иней).
3. **Манифест.** Заполняется `assets-manifest.example.json`: размеры кадра,
   число кадров, fps, петля, **`attach.handR`** (позиция кисти по кадрам — куда
   крепить оружие), **`events`** (кадр→событие, напр. `"3":"hit"` — на каком кадре
   наносится урон, чтобы графика и логика совпадали).
4. **Загрузка.**
   ```js
   import { AssetStore, SpriteRenderer, SilhouetteRenderer } from '../engine/index.js';
   const store = new AssetStore();
   await store.load(manifestJson, (url)=> new Promise((res,rej)=>{ const i=new Image(); i.onload=()=>res(i); i.onerror=rej; i.src=ASSET_BASE+url; }));
   const renderer = new SpriteRenderer(store, new SilhouetteRenderer()); // нет ассета → силуэт-fallback
   ```
   Дальше в цикле — тот же `battle.render(ctx, view, renderer, fx)`.

### Синхронизация графики и логики (важно)
Сейчас урон наносит **симуляция** (по таймеру замаха), а клип удара
проигрывается параллельно. Когда подключишь спрайты с полем `events` (кадр→`hit`),
можно переключить нанесение урона на момент нужного кадра — тогда «удар» на
картинке точно совпадёт с попаданием в модели. Это и есть стык графика↔логика.

## Что брать процедурно, что генерировать
- **Генерировать:** тела/анимации юнитов (спрайт-листы), оружие, крупные оверлеи
  (культя, лёд на части), может — фоновые тайлы.
- **Оставить процедурным (fx.js):** мелкие частицы — брызги крови, искры лязга,
  осколки заморозки, огонь. Дёшево, живо, не требует ассетов.

## Дальнейшее (по ТЗ §8)

`anim/animation.js` (состояния/привязки) и симуляция — остаются.
